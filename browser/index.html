actaseal-verify

Verify a packet in your browser.

This page runs this site's own verify.py, unmodified, inside your browser (Python compiled to WebAssembly). Same checks, same failure codes, same exit code as running it yourself. The packet is read on your machine and is not uploaded.

    What you are trusting. The code that ran is verify.py with SHA-256
    (loading). Compare it with sha256sum verify.py from
    the repository, or skip this page and run
    the CLI yourself. Checks the packet cannot self-certify (the STH key, the TSA chain) stay
    unchecked unless you supply those inputs, and the output says so by name.
  


  

    What this check does not cover.
    
    
      
  • It does not check whose key signed the receipt unless you supply that key or keyring yourself.
        Without one, the result above says so.
    • 
      
  • It does not check the transparency-log key, the timestamp authority's certificate chain, or
        ledger-head anchors unless you supply those inputs. The output names each one it skipped.
    • 
      
  • It does not check the page you were served. A site can serve a verifier that always says
        yes; compare the SHA-256 above with the published file, or run the command-line verifier.
    • 
      
  • It does not say whether the decision itself was right, or whether the evidence the decision
        relied on was true. It says the record is intact, in order, and signed by the stated key.
    • 
    

  


  

    Run it offline. Nothing here needs this site once the files are on your machine,
    but saving this one page is not enough: the browser needs the verifier and its runtime beside it.
    Download the repository, then in that folder run
    python -m http.server 8000, disconnect from the network, and open
    http://localhost:8000/browser/. The result is the same, and no part of it can have
    come from us.
