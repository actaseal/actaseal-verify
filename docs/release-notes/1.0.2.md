# actaseal-verify 1.0.2

Release notes. Not yet tagged or published when this file was written.

## What changed since 1.0.1

**A keyless check for packets: `verify.py --checkpoint HEX`.** When the
key that signed a receipt cannot be trusted or is not known to you
(rotated out, lost, never published to you), supply the hash of a ledger
event you already trust, obtained out of band. The packet then passes on
the chain alone, reported as `CHAIN_VERIFIED_KEY_UNKNOWN` and never as a
signature check, if that hash is in the packet's unbroken slice at or
after the receipt's ledger entry and an event under it records the
receipt's own hash. With a signature that verifies it is one more check.
A key or keyring you supply is never overridden by a checkpoint. New
failure codes: `CHECKPOINT_NOT_IN_SLICE`,
`CHECKPOINT_BEFORE_RECEIPT_ENTRY`, `CHECKPOINT_RECEIPT_NOT_COMMITTED`.

`verify_receipt.py` already had a `--checkpoint` for a bare receipt. Its
rule is unchanged and is weaker than the packet one: it requires the
checkpoint to be in the supplied slice, not that it comes after the
receipt's entry, and a bare receipt carries no record of its own hash in
the chain. Prefer the packet check when you have the packet.

**Comments and help text.** The source files described themselves by
pointing at files of the licensed product. They now describe each check
in terms of this repository and the standards it follows. One printed
note in `verify_receipt.py` changed for the same reason.

**No check was removed or loosened.** Without `--checkpoint`, `verify.py`
is the same program as in 1.0.1 with comments and docstrings set aside,
and every output on every conformance vector and demo packet is
byte-identical, apart from the two verifier-digest vectors, which print
this file's own hash.

## If you hold packets made before this release

A packet may pin the verifier it was shipped with (`verifier_sha256` in
`manifest.json`). That pin is over the verifier's body, comments
included, so it names one exact `verify.py`:

| | |
|---|---|
| `verify.py` body digest in 1.0.2 (the value a packet pins) | `79673240546ae63b88811a99846058bd56a04d44b7776462e1a1622ce7e7e38a` |
| `verify.py` file SHA-256 in 1.0.2 | `844ff9eb8188ddecbbaf4e1c0a76418f0fea4c41dc4cd4ffce8af97a7af957a9` |

Checking a packet that pins an earlier body with this `verify.py`
reports `VERIFIER_DIGEST_MISMATCH`. That is the pin doing its job, not
damage to the packet. Check such a packet with the `verify.py` it
carries, whose hash is the one it pins. The packet format itself is
unchanged: `VERIFIER_SUPPORTS_ROOT_VERSIONS` is still `("v1", "v2")`.

## Conformance vectors

- New group `vectors/packet_checkpoint/` (six cases) with its own runner.
- `vectors/verifier_digest_valid/` is regenerated for this body. It had
  been left pinned to an earlier body when `--help` was added, so
  `conformance/test_conformance.py` was failing on `main` from then
  until this release.
- Every other vector file is unchanged.

## Install

```
pip install actaseal-verify==1.0.2
```

once it is published. Until then, run `verify.py` from a checkout.
